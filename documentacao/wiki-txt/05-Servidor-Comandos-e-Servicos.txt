1. ANTES DE COMEÇAR
-------------------

- Clone do Git (de onde o playbook roda): Na máquina do técnico; numa central instalada de dentro, também /opt/TeliumPABX
- Ajustes desta central: /etc/telium-servidor.yml (root, 0600)
- Código publicado (o que está no ar): /opt/telium
- Utilitário telium: /opt/telium/api/bin/telium
- Usuário de sistema da API: teliumpbx (sem login)

- O telium roda sempre como teliumpbx: sudo -u teliumpbx php /opt/telium/api/bin/telium <comando>. Rodar como root cria arquivos com o dono errado.
- Os comandos de Asterisk, MariaDB e systemd pedem sudo.
- Pelo navegador, Administrador › CLI Asterisk dá um terminal do Asterisk sem SSH.

Mais detalhes sobre os caminhos em Diretórios, arquivos e logs (ver página 06).


2. O UTILITÁRIO TELIUM
----------------------

    sudo -u teliumpbx php /opt/telium/api/bin/telium <comando>

Sem comando (ou com um desconhecido), mostra a versão e a ajuda, com todos os comandos abaixo.

- migrar: Aplica os scripts SQL (/opt/telium/sql). Todos são idempotentes: reaplicar é seguro
- gerar-config: Gera os .conf de /etc/asterisk/telium a partir do banco, sem recarregar
- aplicar-config: Gera e recarrega o Asterisk. É o mesmo que Aplicar configurações no console
- doctor: Testa banco, AMI, Janus (se houver) e a escrita em /etc/asterisk/telium
- senha <usuario>: Define nova senha de um usuário do console
- desligar-2fa <usuario>: Desliga a verificação em dois passos de um usuário (celular perdido)
- alertas: Manda por e-mail os alertas do sistema pendentes (backup, certificado, disco)
- testar: Roda a bateria de testes
- backup-enviar <id>: Envia um backup ao destino remoto
- tarifar [AAAA-MM]: Calcula o custo das chamadas ainda sem custo
- cc-servico: Serviço de tempo real do call center (quem roda é o telium-cc)


migrar
~~~~~~

    sudo -u teliumpbx php /opt/telium/api/bin/telium migrar

- Procura os .sql em SQL_DIR do .env (/opt/telium/sql) e aplica todos, em ordem.
- Mostra ✓ ou ✗ por arquivo e termina com ✓ banco atualizado. Com erro, sai com código 1.
- O playbook já roda as migrações; use à mão só quando orientado.


gerar-config e aplicar-config
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

    sudo -u teliumpbx php /opt/telium/api/bin/telium gerar-config
    sudo -u teliumpbx php /opt/telium/api/bin/telium aplicar-config

- gerar-config lista cada arquivo com inalterado, criado ou atualizado. Com mudança, marca a configuração como pendente (a faixa amarela do console).
- aplicar-config gera e então: sincroniza as listas na base do Asterisk (lista negra, permitida, não perturbe, chamada em espera…) e recarrega, um a um, ramais e troncos (res_pjsip), dialplan, filas, correio de voz, conferências, estacionamento, música em espera, códigos de recurso, colunas do CDR e candidatos ICE. Por fim confere se todos os ramais e troncos carregaram.
- Cada etapa sai como ok ou falhou. Uma falha lista o ramal/tronco que o Asterisk recusou.
- Só uma geração por vez: com outra em andamento, o comando avisa e não faz nada.


doctor
~~~~~~

    sudo -u teliumpbx php /opt/telium/api/bin/telium doctor

- banco: Conecta no MariaDB e conta os ramais
- ami: Faz login no AMI e lê a versão do Asterisk
- janus: Só se o Janus responder em 127.0.0.1:8088; senão mostra "não instalado (opcional)"
- escrita conf: Se a API consegue escrever em /etc/asterisk/telium

Sai com código 0 se tudo passou.


senha
~~~~~

    sudo -u teliumpbx php /opt/telium/api/bin/telium senha admin

- No terminal, pede a senha sem mostrar. Também aceita pela entrada padrão: echo 'NovaSenha' | sudo -u teliumpbx php /opt/telium/api/bin/telium senha admin.
- A senha passa pela mesma regra de força do console.
- Derruba as sessões abertas do usuário e zera o bloqueio por tentativas erradas.
- É o caminho para quem perdeu a senha do admin.
- Não desliga a verificação em dois passos: para isso, use desligar-2fa.


desligar-2fa
~~~~~~~~~~~~

    sudo -u teliumpbx php /opt/telium/api/bin/telium desligar-2fa admin

- Para quando o único administrador perdeu o celular do autenticador e não consegue entrar no console.
- Desliga a verificação em dois passos do usuário, derruba as sessões dele e registra na auditoria (2fa_desligado, origem terminal).
- Depois de entrar, a pessoa liga a verificação de novo em Meu Perfil e Segurança.


alertas
~~~~~~~

    sudo -u teliumpbx php /opt/telium/api/bin/telium alertas

- Confere e manda por e-mail os alertas do sistema para os endereços de Configurações › Notificações e E-mail › Mandar os alertas do sistema para (Configurações (ver página 19)).
- São quatro: backup que falhou (nas últimas 24 h), nenhum backup concluído há mais de 26 horas com alguma rotina ligada, certificado do console (o que o nginx apresenta na porta 443) a menos de 15 dias de vencer ou vencido, e disco das gravações com menos de 10% livre.
- Cada alerta sai no máximo uma vez por dia; o de backup com falha, uma vez por backup. A marca do último envio fica na tabela sistema (chaves alerta_…).
- Não manda nada se o envio de e-mail estiver desligado ou o campo dos alertas estiver em branco.
- Mostra o assunto de cada alerta enviado, ou nenhum aviso a mandar.
- Não precisa rodar à mão: o executor de backup (telium-backup) o chama de hora em hora (no minuto 07) e logo depois de um backup que falha. Rodar à mão serve para testar o envio.


testar
~~~~~~

    sudo -u teliumpbx php /opt/telium/api/bin/telium testar

Bateria de verificação da instalação (banco, configuração gerada, Asterisk, áudios, permissões, certificados, segurança da API e outros). Termina com ✓ N testes, nenhuma falha ou lista o que falhou, saindo com código 1. O playbook roda a bateria no fim e para se ela falhar. Sem banco, roda só os testes que não dependem dele.


backup-enviar
~~~~~~~~~~~~~

    sudo -u teliumpbx php /opt/telium/api/bin/telium backup-enviar 42

- 0: Enviado, ou nenhum destino remoto ligado
- 1: Falha no envio (ou backup não encontrado)
- 64: Uso errado (sem id)

O resultado fica registrado e aparece na tela de backup. Veja Backup e Restauração (ver página 04).


tarifar
~~~~~~~

    sudo -u teliumpbx php /opt/telium/api/bin/telium tarifar            # o que falta, de qualquer mês
    sudo -u teliumpbx php /opt/telium/api/bin/telium tarifar 2026-09    # só aquele mês

- Chamada já tarifada não é recalculada. Para refazer um mês inteiro com os preços de agora, use Recalcular o mês em Telium › Tarifação (Tarifação (ver página 20)).
- Avisa quando todas as tarifas estão com preço zero e quando há chamadas sem tarifa que se aplique.
- Roda sozinho de hora em hora pelo telium-tarifar.timer.


cc-servico
~~~~~~~~~~

Escuta os eventos de fila do Asterisk e alimenta os painéis do call center em 127.0.0.1:8095. Também é ele que manda os webhooks de chamada (chamada.tocando, chamada.atendida, chamada.encerrada) cadastrados em Telium › Integrações / API. Não rode à mão: quem o mantém no ar é o serviço telium-cc (seção 5).


3. SCRIPTS EM /USR/LOCAL/SBIN
-----------------------------

Instalados pelo Ansible. Quase todos rodam como root e não recebem argumentos (exceto o telium-fail2ban): leem o que fazer no banco. A API os aciona por regras de sudo próprias em /etc/sudoers.d. O telium-fax-email é a exceção: quem o chama é o Asterisk, com argumentos.

- telium-backup — Para que serve: Executa a restauração pedida, apaga os backups marcados para excluir, roda as rotinas vencidas e os backups na fila; uma vez por dia, apaga as gravações que passaram do prazo de guarda; de hora em hora (no minuto 07) e logo depois de um backup que falha, roda telium alertas; Quem aciona: Console + telium-backup.timer
- telium-certificados — Para que serve: Aplica certificados pendentes no nginx, Asterisk (SIP TLS), coturn e Janus; volta o anterior se o serviço recusar; Quem aciona: Console + telium-certificados.timer
- telium-smtp — Para que serve: Gera a configuração do msmtp (envio de recado por e-mail) a partir da tabela smtp; Quem aciona: Console (ao salvar o e-mail) e playbook
- telium-fail2ban — Para que serve: Ponte do console com o fail2ban: lista e desbane IPs, aplica a lista "Nunca bloquear" (e, com o SIP só para redes conhecidas, reaplica o telium-firewall-sip); Quem aciona: Console (Conectividade › Firewall) e playbook
- telium-firewall-sip — Para que serve: SIP só para redes conhecidas: monta (aplicar), apaga (desligar) ou mostra (mostrar) a tabela inet telium_sip do nftables, com as redes fixas, o "Nunca bloquear", os troncos e os telefones já registrados. Sem /etc/telium-sip-redes.conf, fica desligado. Veja Segurança (ver página 08); Quem aciona: telium-firewall-sip.timer, telium-fail2ban confiaveis e playbook
- telium-despertador — Para que serve: Liga para os ramais com despertador marcado (pelo *68 ou pelo console). Se ninguém atende, tenta de novo: o despertador do console, quantas vezes e com o intervalo do cadastro; o do *68, mais duas vezes, a cada dois minutos. As tentativas em curso ficam em /var/lib/telium/despertador, e o resultado (atendeu ou não atendeu) vai para o cadastro; Quem aciona: telium-despertador.timer
- telium-fax-email — Para que serve: Manda o fax recebido por e-mail: converte o TIFF em PDF (com o tiff2pdf, do pacote libtiff-tools; sem ele, vai o TIFF) e envia pelo mesmo sendmail (msmtp) do recado do correio de voz. Só aceita arquivo em /var/spool/asterisk/fax e registra o resultado no syslog com a marca telium-fax; Quem aciona: O Asterisk, ao fim de cada fax recebido, quando há e-mail em Configurações › Fax (roda como asterisk)

Uso à mão:

    sudo /usr/local/sbin/telium-backup                   # processa o que estiver pendente (não cria backup novo)
    sudo /usr/local/sbin/telium-certificados             # aplica atribuições pendentes
    sudo /usr/local/sbin/telium-certificados servicos    # lista os serviços que sabe atualizar
    sudo /usr/local/sbin/telium-smtp                     # republica a configuração de e-mail
    sudo /usr/local/sbin/telium-fail2ban listar          # banidos, em JSON
    sudo /usr/local/sbin/telium-fail2ban desbanir asterisk 203.0.113.10
    sudo /usr/local/sbin/telium-fail2ban confiaveis      # reaplica a lista "Nunca bloquear"
    sudo /usr/local/sbin/telium-firewall-sip mostrar     # SIP por rede: a tabela em vigor, ou "desligado"
    sudo /usr/local/sbin/telium-firewall-sip aplicar     # remonta a lista agora (tronco novo, sem esperar o timer)

NOTA: Os scripts são gerados pelo playbook ("Não edite à mão"). Mudança feita direto neles some na próxima atualização.


4. SCRIPTS DE DIAGNÓSTICO
-------------------------

Ficam no clone, não no código publicado. Numa central instalada de fora não há clone no servidor: rode os scripts da sua máquina, na pasta do clone, com ssh root@200.170.198.176 'bash -s' < infra/diagnostico.sh (o mesmo para o diagnostico-ami.sh), e o verificar.yml com ansible-playbook -i "200.170.198.176," verificar.yml -u root -k (em infra/ansible).

- sudo bash /opt/TeliumPABX/infra/diagnostico.sh: Relatório curto: serviços, versões, portas em escuta, contagens do banco, endpoints e ODBC do Asterisk, Janus, /api/health, arquivos gerados e erros recentes. A saída é feita para colar inteira num chamado
- sudo bash /opt/TeliumPABX/infra/diagnostico-ami.sh: Quando o AMI recusa o login: confere a porta 5038, os usuários do manager, compara a senha do manager.conf com a origem usada pelo Ansible (sem mostrá-la inteira), tenta um login real e mostra o manager.conf com a senha mascarada
- cd /opt/TeliumPABX/infra/ansible && sudo ansible-playbook verificar.yml: Diagnóstico completo pelo Ansible. É a saída a mandar ao pedir ajuda

NOTA: O diagnostico.sh confere janus na lista de serviços; numa central sem Janus ele aparece como inativo, o que é normal.


5. SERVIÇOS
-----------

- asterisk — O que faz: A central telefônica; Observação: Roda como asterisk. systemctl reload asterisk faz core reload
- telium-cc — O que faz: Tempo real do call center: painéis, códigos de agente no telefone, retornos; e o envio dos webhooks de chamada; Observação: Roda como teliumpbx, reinicia sozinho se cair. Sem ele o console funciona, mas o telefone não loga agente
- mariadb — O que faz: Banco telium_pabx; Observação: Escuta só em 127.0.0.1
- nginx — O que faz: HTTPS do console, API, /ws do softphone
- php8.4-fpm — O que faz: Executa a API (pool telium, socket /run/php/telium.sock)
- coturn — O que faz: TURN do softphone do navegador; Observação: Instalado por padrão (instalar_turn)
- fail2ban — O que faz: Bane IPs que erram senha (SIP, console, SSH)
- janus — O que faz: Gateway WebRTC opcional; Observação: Só existe com instalar_janus=true; o softphone não precisa dele
- zabbix-agent2 — O que faz: Agente do Zabbix (Monitoria pelo Zabbix); Observação: Instalado na instalação nova (instalar_zabbix); a atualização não mexe nele. Porta 10050, aberta só para os servidores Zabbix
- asterniclog — O que faz: Asternic (opcional): lê /var/log/asterisk/queue_log para o banco qstats; Observação: Só existe com instalar_asternic: true. O Asternic roda no pool asternic do PHP-FPM (/run/php/asternic.sock)

Comandos:

    systemctl is-active mariadb nginx php8.4-fpm asterisk telium-cc coturn fail2ban
    sudo systemctl status asterisk
    sudo systemctl restart telium-cc
    journalctl -u telium-cc -f
    journalctl -u asterisk -n 100 --no-pager

NOTA: ⚠️ systemctl restart asterisk derruba todas as chamadas. Para reiniciar sem cortar ninguém: sudo asterisk -rx "core restart when convenient" (espera a central ficar sem chamadas).

O Asterisk depende do MariaDB de forma fraca (Wants): reiniciar o MariaDB não reinicia o Asterisk.


Monitoria pelo Zabbix
~~~~~~~~~~~~~~~~~~~~~

Na instalação nova (pergunta "Monitorar? [S/n]", instalar_zabbix), o playbook instala o zabbix-agent2 do Debian e configura o que está abaixo. A atualização não mexe em nada disso. Numa central já instalada, configure pedindo: -e zabbix_configurar=true.

As senhas do AMI e do banco são as do Zabbix da Telium, as mesmas em todas as centrais. Elas ficam em infra/ansible/zabbix-senhas.yml, que vai no repositório (privado): quem clona já recebe e a instalação não pede nada. Para instalar sem monitoria: -e instalar_zabbix=false.


- Servidores Zabbix (Server=, ServerActive=) e o nome da central no Zabbix (Hostname=, o hostname -a da máquina, ou o hostname): /etc/zabbix/zabbix_agent2.conf
- Itens do Asterisk (asterisk.*: canais, chamadas, endpoints PJSIP, filas, uptime, versão, erros e avisos do log): /etc/zabbix/zabbix_agent2.d/asterisk_plugin.conf
- Script que consulta o Asterisk pelo AMI: /Telium/zabbix/scripts/zbx_asterisk_ami.py
- Itens do sistema Telium (telium.*: nome, versão, saúde da API, certificado, backup): /etc/zabbix/zabbix_agent2.d/telium.conf e /Telium/zabbix/scripts/zbx_telium.sh
- Pacotes com atualização (pacotes.updates.count): /etc/zabbix/zabbix_agent2.d/debian_updates.conf e /Telium/zabbix/scripts/check_pacotes_updates.sh (a hora da última verificação fica em run/). A lista de pacotes é baixada uma vez por dia pelo apt-daily.timer (/etc/apt/apt.conf.d/20telium-listas); nada é instalado sozinho
- Usuário zabbix do AMI (só 127.0.0.1): /etc/asterisk/manager_custom.conf (o playbook só acrescenta, e nunca reescreve; se já houver um [zabbix], fica o que está); a senha do script em /etc/zabbix/telium-ami.conf
- Usuário zbx_monitor do banco, para localhost, 127.0.0.1 e 198.18.22.114 (sessão Default e itens sem parâmetro): /etc/zabbix/zabbix_agent2.d/plugins.d/mysql.conf
- Status do nginx: http://127.0.0.1:8080/nginx_status (/etc/nginx/conf.d/zabbix-status.conf)
- Usuário zabbix_test do teste de SSH: /home/zabbix_test/.ssh/authorized_keys (e o link em /etc/ssh/keys/zabbix_test/ quando o sshd usa essa pasta)

Itens do sistema Telium, para o template PBX - TeliumPABX (Asterisk, nginx e MariaDB ficam nos templates próprios). O template pronto para o Zabbix 7.4, com estes itens e os alertas (certificado vencendo, backup falhou ou atrasado, serviço parado, API com problema), está em infra/zabbix/PBX-TeliumPABX.yaml: Coleta de dados › Templates › Importar. Importar de novo atualiza o que já existe.

- telium.servername: O nome da central (o server_name do console no nginx)
- telium.versao: A versão do Telium PABX
- telium.saudavel: 1 se o /api/health responde com o banco, o esquema e o Asterisk em ordem; 0 se não
- telium.ssl.dias: Dias até o certificado que o nginx entrega na 443 vencer (negativo: venceu)
- telium.ssl.expira: O vencimento, em unixtime
- telium.ssl.emissor: Quem emitiu o certificado
- telium.ssl.nome_confere: 1 se o certificado vale para o nome da central
- telium.backup.horas: Horas desde o último backup concluído (-1: nenhum)
- telium.backup.ok: 1 se a última execução deu certo, 0 se falhou (-1: nenhuma terminou)
- telium.backup.tamanho: Bytes do último backup concluído
- telium.backup.rotinas: Rotinas de backup agendadas e ativas
- telium.backup.remoto.estado: Envio ao destino remoto: desligado, nunca, ok ou falha
- telium.backup.remoto.horas: Horas desde o último envio (-1: nunca)
- systemd.unit.info["<unidade>"]: Do próprio agent2, sem script: active quando roda. Unidades do Telium: telium-cc.service, php8.4-fpm.service, coturn.service, telium-backup.timer, telium-certificados.timer, telium-despertador.timer, telium-tarifar.timer

O backup é lido como zbx_monitor, que só enxerga as colunas de estado (/etc/zabbix/telium-db.cnf, root:zabbix 0640); a senha do FTP do destino remoto fica de fora.

Conferir no servidor:

    systemctl status zabbix-agent2
    cd /etc/zabbix && sudo zabbix_agent2 -t 'mysql.ping[Default]'      # 1 = banco respondendo
    sudo -u zabbix /Telium/zabbix/scripts/zbx_asterisk_ami.py version    # versão do Asterisk
    sudo -u zabbix /Telium/zabbix/scripts/zbx_asterisk_ami.py debug.pjsip
    sudo -u zabbix /Telium/zabbix/scripts/zbx_telium.sh dias            # dias até o certificado vencer
    sudo -u zabbix /Telium/zabbix/scripts/zbx_telium.sh backup.horas
    cd /etc/zabbix && sudo zabbix_agent2 -t pacotes.updates.count
    curl -s http://127.0.0.1:8080/nginx_status
    tail -f /var/log/zabbix/zabbix_agent2.log

O zabbix_agent2 -t tem de ser rodado de dentro de /etc/zabbix: o pacote inclui os plugins por caminho relativo, e de outra pasta o teste do MySQL ignora o usuário configurado (e acusa "Access denied for user 'root'").

Central configurada à mão antes: a atualização não mexe nela. Com -e zabbix_configurar=true, um [zabbix] que já esteja no manager_custom.conf fica como está.


6. TEMPORIZADORES (TIMERS)
--------------------------

- telium-backup.timer — Executa: telium-backup.service → /usr/local/sbin/telium-backup (e, por ele, a limpeza diária das gravações e os alertas de hora em hora); Quando (OnCalendar): A cada minuto (*:0/1)
- telium-certificados.timer — Executa: telium-certificados.service → /usr/local/sbin/telium-certificados; Quando (OnCalendar): A cada minuto (*:0/1)
- telium-despertador.timer — Executa: telium-despertador.service → /usr/local/sbin/telium-despertador; Quando (OnCalendar): A cada minuto (*:0/1)
- telium-tarifar.timer — Executa: telium-tarifar.service → telium tarifar (como teliumpbx); Quando (OnCalendar): De hora em hora (hourly)
- telium-firewall-sip.timer — Executa: telium-firewall-sip.service → /usr/local/sbin/telium-firewall-sip aplicar; Quando (OnCalendar): 30 s depois do boot e a cada 5 minutos. Ligado só com sip_restringir_redes

Rodar a cada minuto não quer dizer trabalhar a cada minuto: cada um olha o banco e sai com "nada a fazer" quando não há pendência.

    systemctl list-timers 'telium-*'
    journalctl -u telium-backup -n 50 --no-pager
    journalctl -u telium-certificados -n 50 --no-pager
    journalctl -u telium-despertador -n 50 --no-pager
    journalctl -u telium-tarifar -n 50 --no-pager
    sudo systemctl start telium-tarifar.service      # roda agora, fora de hora

7. ASTERISK
-----------

Entrar no console do Asterisk: sudo asterisk -rvvv (sair com exit). Um comando avulso: sudo asterisk -rx "<comando>".


Estado geral
~~~~~~~~~~~~

- core show uptime: Há quanto tempo está no ar e o último reload
- core show version: Versão
- core show channels: Chamadas em curso
- core show settings: Configuração em uso (idioma, limites)


Ramais e troncos (PJSIP)
~~~~~~~~~~~~~~~~~~~~~~~~

- pjsip show endpoints: Ramais e troncos carregados e o estado
- pjsip show endpoint 1001: Detalhe de um ramal
- pjsip show contacts: Aparelhos registrados (IP, latência)
- pjsip show registrations: Registro da central na operadora
- pjsip show transports: Transportes udp, tcp, tls e wss
- pjsip set logger on / off: Mostra as mensagens SIP no console (depuração)
- rtp set debug on / off: Mostra os pacotes de áudio (depuração; muito verboso)

NOTA: O sip set debug não existe nesta central: o Asterisk 22 só tem PJSIP. Use pjsip set logger on.


Filas, dialplan e recarga
~~~~~~~~~~~~~~~~~~~~~~~~~

- queue show: Filas, membros e quem espera
- queue show <fila>: Uma fila
- dialplan show telium-ramais: Um contexto do dialplan
- dialplan reload: Relê o dialplan
- core reload: Relê toda a configuração
- database show <família>: Base interna (ex.: database show dnd, database show sigame)
- odbc show all: Conexão do Asterisk com o banco (CDR, queue_log)
- manager show users: Usuários do AMI
- logger reload: Reabre os arquivos de log

NOTA: Prefira Aplicar configurações (ou telium aplicar-config) a core reload: ele gera os arquivos a partir do banco antes de recarregar e confere o resultado. Um reload sem gerar só relê o que já estava no disco.


Exemplos
~~~~~~~~

    sudo asterisk -rx "pjsip show contacts"
    sudo asterisk -rx "pjsip show registrations"
    sudo asterisk -rx "queue show"
    sudo asterisk -rx "core show channels"


8. MARIADB
----------

O root do MariaDB entra pelo socket, sem senha, com sudo:

    sudo mariadb telium_pabx

A senha do usuário da aplicação (telium) fica em /etc/telium/credenciais/db_senha; não é preciso para o dia a dia.

Tabelas mais consultadas:

- ramais, troncos: Cadastro de ramais e troncos
- filas, fila_agentes: Filas e membros
- rotas_entrada, rotas_saida: Rotas
- usuarios, perfis, sessoes: Contas do console
- cdr, cel: Registro das chamadas
- queue_log: Eventos das filas (relatórios de call center)
- cc_agentes, cc_atendimentos, cc_retornos: Call center
- sistema: Ajustes gerais (ex.: config_pendente, gravacoes_reter_dias, a marca do último envio de cada alerta)
- backups, backup_rotinas: Backup
- auditoria: Quem fez o quê no console

Exemplos:

    SELECT numero, nome FROM ramais ORDER BY numero;
    SELECT calldate, src, dst, disposition FROM cdr ORDER BY calldate DESC LIMIT 20;

Dump do banco:

    sudo mariadb-dump --single-transaction --routines --triggers telium_pabx | gzip > /root/telium_pabx-$(date +%F).sql.gz

NOTA: Não altere tabelas à mão sem orientação: o console confere regras que o SQL direto ignora. Depois de qualquer mudança feita no banco, rode telium aplicar-config.

----------------------


ufw
~~~

    sudo ufw status numbered

Portas liberadas pelo playbook: veja Requisitos de rede e portas (ver página 03).


SIP só para redes conhecidas
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Opcional (sip_restringir_redes, perguntado na instalação). Uma tabela própria do nftables na frente do ufw, só para as portas de voz:

    sudo telium-firewall-sip mostrar                  # a tabela, com os contadores de descarte
    sudo nft list table inet telium_sip               # o mesmo, direto no nftables
    systemctl status telium-firewall-sip.timer
    journalctl -t telium-firewall-sip                 # o que o aplicar registrou

Detalhes em Segurança (ver página 08).


fail2ban
~~~~~~~~

Cadeias (jails) da central:

- asterisk (UDP) e asterisk-tcp — Vigia: /var/log/asterisk/security, portas 5060 e 5061; Tentativas: 5 em 10 min; Banimento: 24 h
- telium-console — Vigia: /var/log/nginx/access.log, login do console que volta 401/429; Tentativas: 15 em 10 min; Banimento: 1 h
- sshd — Vigia: SSH; Tentativas: padrão: 5 em 10 min; Banimento: 1 h

    sudo fail2ban-client status                       # lista as jails
    sudo fail2ban-client status asterisk              # banidos naquela jail
    sudo fail2ban-client set asterisk unbanip 203.0.113.10

Pelo console: Conectividade › Firewall lista e desbloqueia, e a lista Nunca bloquear vira o ignoreip em /etc/fail2ban/jail.d/telium-confiaveis.local (não edite esse arquivo à mão).

11. LOGS
--------

- Asterisk (completo): sudo tail -f /var/log/asterisk/full
- Asterisk (avisos e erros): sudo tail -f /var/log/asterisk/messages
- Asterisk (segurança, falhas de senha): sudo tail -f /var/log/asterisk/security
- API: sudo tail -f /var/log/telium/php-api.log
- Envio de e-mail: sudo tail -f /var/log/telium-smtp.log
- Fax por e-mail: journalctl -t telium-fax
- nginx: sudo tail -f /var/log/nginx/error.log e access.log
- MariaDB: sudo tail -f /var/log/mysql/error.log
- Serviços Telium: journalctl -u telium-cc -f (e telium-backup, telium-certificados, telium-despertador, telium-tarifar). Os alertas por e-mail aparecem no telium-backup com o prefixo alertas:; os erros de webhook, no telium-cc com o prefixo webhook:
- coturn, fail2ban: journalctl -u coturn, journalctl -u fail2ban

Rotação e localização de cada arquivo em Diretórios, arquivos e logs (ver página 06).


12. PROBLEMAS COMUNS
--------------------


"Permission denied" ao rodar o telium
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Rode como teliumpbx: sudo -u teliumpbx php /opt/telium/api/bin/telium …. Rodando como root, arquivos gerados ficam com o dono errado e a API deixa de conseguir regravá-los; corrija com outro aplicar-config como teliumpbx ou rodando o playbook.


doctor acusa o AMI
~~~~~~~~~~~~~~~~~~

    sudo systemctl status asterisk
    sudo bash /opt/TeliumPABX/infra/diagnostico-ami.sh


"Outra aplicação de configuração está em andamento"
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Alguém está aplicando pelo console (ou outro comando está rodando). Espere alguns segundos e repita.


O telefone não loga agente (*11)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

O telium-cc está parado: sudo systemctl restart telium-cc e journalctl -u telium-cc -n 50.


Mudei um .conf à mão e a mudança sumiu
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Os arquivos de /etc/asterisk/telium são regerados a cada Aplicar configurações, e os de /etc/asterisk a cada playbook. Personalização vai no _custom.conf correspondente (pjsip_custom.conf, extensions_custom.conf, queues_custom.conf, voicemail_custom.conf…), e usuário extra do AMI ou do ARI em /etc/asterisk/manager_custom.conf ou ari_custom.conf: nem o console nem o playbook sobrescrevem esses arquivos. Veja Diretórios, arquivos e logs (ver página 06).
